# 오류·장애 처리 정책

## 1. 목적
오류나 장애가 생겨도 사용자가 상황을 이해하고 다음 행동을 할 수 있도록 입력 오류, 시스템 오류, 에러 페이지(403·404·500), 점검·장애 운영 기준을 하나로 정의한다.
- 범위: 입력 오류 → 시스템·네트워크 오류 → 에러 페이지 → 점검·장애 안내 → 복구
- 다른 정책으로 넘김: 권한 없음 상세 규칙(→ 권한), 오류 문구의 개인정보 노출 금지(→ 개인정보 처리), 점검 공지 배너(→ 알림), 팝업 문구(→ 팝업·문구 S4·S5·S6·S7·D6)

## 2. 규칙 표
| 유형 | 항목 | 대상 | 내용 | 등급 | {변수} |
|---|---|---|---|---|---|
| 입력 오류 | 인라인 오류 | 공통 | 입력 필드 바로 아래 문장으로 안내한다. 아이콘과 텍스트를 함께 써서 색만으로 구분하지 않는다 | 필수 | — |
| 입력 오류 | 오류 문구 | 공통 | 무엇이 잘못됐는지와 고치는 방법을 함께 안내한다. 사용자를 탓하는 표현과 개발 용어는 쓰지 않는다 | 필수 | — |
| 입력 오류 | 제출 시 처리 | 공통 | 제출하면 첫 번째 오류 필드로 초점을 옮긴다. 오류가 나도 입력값은 유지한다 (비밀번호 제외) | 필수 | — |
| 시스템 오류 | 일시적 오류 | 공통 | 오류 팝업으로 안내하고 [다시 시도] 버튼을 제공한다. 문의할 때 쓸 수 있게 오류 코드를 함께 보여 준다 (팝업 S6) | 필수 | — |
| 시스템 오류 | 네트워크 오류 | 공통 | 인터넷 연결을 확인하라고 안내한다 (팝업 S5). 연결이 복구되면 자동으로 다시 시도할 수 있다 | 권장 | — |
| 시스템 오류 | 중요 작업 오류 | 사용자 | 저장·결제 등 중요한 작업은 처리 결과를 확인할 수 있게 안내한다. 처리 중에는 버튼을 비활성으로 두어 중복 실행을 막는다 | 필수 | — |
| 에러 페이지 | 403 권한 없음 | 사용자 | 접근 권한이 없다는 사실과 이유를 알린다. 이전 페이지·홈 이동과 권한 요청 경로를 제공한다 (팝업 S4) | 필수 | — |
| 에러 페이지 | 404 페이지 없음 | 공통 | 주소가 바뀌었거나 삭제된 페이지임을 알린다. 홈 이동과 주요 메뉴 링크를 제공한다 | 필수 | — |
| 에러 페이지 | 500 서버 오류 | 공통 | 잠시 후 다시 시도하라고 안내한다. 새로고침·홈 이동과 {문의 채널}, 오류 코드를 제공한다 | 필수 | 문의 채널 |
| 점검·장애 운영 | 점검 사전 안내 | 공통 | 점검 일시와 영향 범위를 {사전 공지: 3일 전}에 공지하고, 로그인 후 팝업·배너로 한 번 더 안내한다 (팝업 S7) | 필수 | 사전 공지 |
| 점검·장애 운영 | 점검 중 화면 | 공통 | 점검 시간과 종료 예정 시각을 보여 주고 문의 채널을 제공한다 | 필수 | — |
| 점검·장애 운영 | 장애 공지·기록 | 관리자 | 장애가 생기면 공지하고 복구 예정 시간을 안내한다. 오류 로그를 기록하되 로그와 화면에 개인정보를 넣지 않는다 | 필수 | — |

## 3. 흐름 (오류 발생 시 처리)
![오류 발생 시 처리 흐름. 발생: 사용자가 화면 이동·저장·조회를 요청하다 오류가 발생하면 오류 유형(입력·권한·페이지·서버)을 판단합니다. 판단: 서버·네트워크 오류는 오류 코드와 함께 팝업으로 알리고 입력값을 유지한 채 다시 시도하게 합니다. 여러 번 실패하면 500 에러 페이지나 장애 공지와 함께 문의 채널을 안내합니다. 안내: 재시도에 성공하면 요청을 정상 처리하고 토스트나 완료 화면으로 결과를 알립니다. 복구: 사용자는 원래 화면에서 작업을 이어서 진행합니다.](/flows/error.svg)

## 4. 예시 문구 (합니다체)
| 상황 | 문구 |
|---|---|
| 필수 입력 누락 | {항목명}을 입력해 주십시오. (팝업 D6) |
| 형식 오류 | 이메일 형식이 올바르지 않습니다. 예: name@example.com |
| 일시적 오류 | 일시적인 오류가 발생했습니다. 잠시 후 다시 시도해 주십시오. (오류 코드: {코드}) (팝업 S6) |
| 네트워크 오류 | 인터넷 연결을 확인한 뒤 다시 시도해 주십시오. (팝업 S5) |
| 중요 작업 처리 중 | 처리 중입니다. 작업이 끝날 때까지 화면을 닫지 마십시오. |
| 403 | 이 페이지에 접근할 권한이 없습니다. 필요하면 관리자에게 권한을 요청해 주십시오. |
| 404 | 요청하신 페이지를 찾을 수 없습니다. 주소가 바뀌었거나 삭제된 페이지입니다. |
| 500 | 서비스에 일시적인 문제가 생겼습니다. 잠시 후 다시 시도해 주십시오. 문제가 계속되면 {문의 채널}로 알려 주십시오. (오류 코드: {코드}) |
| 점검 사전 안내 | {점검 일시}에 서비스 점검이 진행됩니다. 점검 중에는 {영향 범위}을 이용할 수 없습니다. (팝업 S7) |
| 점검 중 화면 | 서비스 점검 중입니다. {종료 예정 시각}에 다시 이용할 수 있습니다. |
| 장애 공지 | 현재 {장애 내용}으로 이용이 원활하지 않습니다. {복구 예정 시간}까지 복구할 예정입니다. |

## 5. 체크리스트
- [ ] 입력 오류가 필드 아래 문장으로, 아이콘과 텍스트로 함께 표시되는가
- [ ] 오류 문구에 원인과 해결 방법이 있고, 탓하는 표현·개발 용어가 없는가
- [ ] 제출 시 첫 오류 필드로 초점이 가고, 입력값이 유지되는가
- [ ] 시스템 오류 팝업에 [다시 시도]와 오류 코드가 있는가
- [ ] 중요 작업 중 버튼이 비활성되어 중복 실행이 막히는가
- [ ] 403·404·500 페이지에 이유와 이동 경로(이전·홈·문의)가 있는가
- [ ] 점검은 미리 공지하고, 점검 중 화면에 종료 예정 시각이 있는가
- [ ] 오류 로그와 화면에 개인정보가 들어가지 않는가
