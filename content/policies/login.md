# 로그인 정책

## 1. 목적
사용자가 서비스에 안전하고 빠르게 접근할 수 있도록 로그인 방식, 로그인 보조, 로그인 후 연결, 보안·운영 기준을 하나로 정의한다. (웹 데스크톱 기준)
- 범위: 로그인 화면 진입 → 인증(기본·SNS·패스키, 2차 인증) → 로그인 후 이동 → 세션 유지·만료
- 다른 정책으로 넘김: 가입(→ 회원가입), 비밀번호 규칙·재설정(→ 비밀번호), 메뉴 노출 권한(→ 권한·역할), 팝업 문구(→ 팝업·문구 S1·S2·A1·A2)

## 2. 규칙 표
| 유형 | 항목 | 대상 | 내용 | 등급 | {변수} |
|---|---|---|---|---|---|
| 로그인 방식 | 기본 로그인 | 공통 | 아이디·비밀번호로 로그인한다. 플레이스홀더는 '레이블명 + 입력해주세요.' 형식으로 쓰고, 입력 규칙은 helper text로 안내한다. 비밀번호 표시/숨김 토글을 제공하고 Enter 키로 로그인을 실행한다 | 필수 | — |
| 로그인 방식 | SNS 간편 로그인 | 사용자 | {SNS 종류: 카카오·네이버·구글}을 사용량 순서로 노출한다. 팝업 또는 리다이렉트 방식으로 인증하고, 팝업이 차단되면 안내 문구를 보여 준다. 가입 이력이 없으면 간편 가입으로 연결한다 | 선택 | SNS 종류 |
| 로그인 방식 | 패스키 인증 | 사용자 | WebAuthn 기반 패스키를 지원 환경에서만 노출하고, 미지원 환경은 기본 로그인으로 대체한다. 기기 등록·삭제는 내 정보에서 관리한다 | 선택 | — |
| 로그인 보조 | 최근 로그인 방식 안내 | 사용자 | 마지막으로 사용한 로그인 방식을 강조해 보여 주되, 다른 방식도 고를 수 있게 한다 | 권장 | — |
| 로그인 보조 | 다중 계정 전환 | 사용자 | 로그인 후 계정 메뉴에서 전환을 제공하고, 전환 전에 현재 작업 저장 여부를 확인한다 | 선택 | — |
| 로그인 보조 | 로그인 상태 유지 | 사용자 | 체크박스로 선택하게 하고 기본값은 해제다. 공용 기기 사용 시 주의 안내를 함께 둔다. 유지 기간 {상태 유지: 30일} | 권장 | 상태 유지 |
| 로그인 후 연결 | 원래 작업으로 복귀 | 공통 | 로그인이 필요한 기능에 접근했다가 로그인하면 해당 화면·작업으로 돌아간다. 입력 중이던 정보는 유지한다 | 필수 | — |
| 로그인 후 연결 | 로그인 필요 안내 | 비회원 | 비로그인 상태에서 제한 기능에 접근하면 안내 문구와 로그인 버튼을 보여 준다. 취소하면 기존 화면을 유지한다 | 필수 | — |
| 로그인 후 연결 | 기본 이동 화면 | 사용자 · 관리자 | 복귀할 작업이 없으면 권한별 기본 화면으로 이동한다. {기본 화면: 사용자 메인 · 관리자 대시보드} | 권장 | 기본 화면 |
| 보안/운영 | 로그인 실패 처리 | 공통 | 계정 존재 여부를 알 수 없도록 통일된 오류 문구를 쓴다. 연속 {CAPTCHA 노출: 3회} 실패 시 CAPTCHA를 보여 주고, {계정 잠금: 5회} 실패 시 로그인을 제한한다 (팝업 A2) | 필수 | CAPTCHA 노출, 계정 잠금 |
| 보안/운영 | 2차 인증 (휴대폰) | 공통 | 아이디·비밀번호 확인 후 휴대폰 번호를 입력받고, 그 번호로 보낸 인증번호를 웹 화면에 입력해야 로그인이 완료된다. 인증번호 유효 시간 {유효 시간: 5분}, 남은 시간 표시, 재발송 {재발송 제한: 1분에 1회} | 선택 | 유효 시간, 재발송 제한 |
| 보안/운영 | 세션 만료 | 공통 | 마지막 활동 후 {세션 유지: 1시간}이 지나면 세션이 만료된다. 만료 {남은 시간: 5분} 전에 경고와 연장 버튼을 보여 준다 (팝업 S1). 만료되면 로그인 화면으로 이동하고 (팝업 S2), 다시 로그인하면 원래 작업으로 복귀한다 | 권장 | 세션 유지, 남은 시간 |
| 보안/운영 | 접근성 | 공통 | KWCAG 2.2 접근 가능한 인증 기준을 지킨다. 반복 입력 정보 자동 완성을 허용하고, 키보드 조작과 초점 이동 순서를 보장한다 | 필수 | — |

## 3. 흐름
![로그인 흐름. 진입: 비로그인 사용자가 로그인 화면에 들어옵니다(직접 진입 또는 로그인 필요 기능 접근). 인증: 기본 로그인, SNS 간편 로그인, 패스키 인증 중 하나로 인증하고, SNS는 가입 이력이 없으면 간편 가입으로 연결합니다. 완료: 인증 성공 후 복귀할 작업이 있으면 원래 페이지로, 없으면 권한별 기본 화면으로 이동합니다. 2차 인증을 쓰면 휴대폰 인증번호를 입력한 뒤 이동합니다.](/flows/login.svg)

## 4. 예시 문구 (합니다체)
| 상황 | 문구 |
|---|---|
| 아이디 플레이스홀더 | 아이디를 입력해주세요. |
| 로그인 실패 | 아이디 또는 비밀번호가 올바르지 않습니다. |
| CAPTCHA 노출 | 로그인 시도가 여러 번 실패했습니다. 자동 입력 방지 문자를 입력해 주십시오. |
| 계정 잠금 | 비밀번호를 {계정 잠금} 잘못 입력해 계정이 잠겼습니다. 비밀번호를 재설정해 주십시오. (팝업 A2) |
| SNS 팝업 차단 | 팝업이 차단되어 로그인 창을 열 수 없습니다. 브라우저에서 팝업을 허용해 주십시오. |
| 최근 로그인 방식 | 최근에 {로그인 방식}(으)로 로그인했습니다. |
| 로그인 상태 유지 주의 | 공용 기기에서는 로그인 상태 유지를 사용하지 마십시오. |
| 로그인 필요 안내 | 로그인이 필요한 기능입니다. 로그인하시겠습니까? |
| 2차 인증번호 발송 | {휴대폰 번호}로 인증번호를 보냈습니다. {유효 시간} 안에 입력해 주십시오. |
| 2차 인증번호 오류 | 인증번호가 일치하지 않습니다. 다시 확인해 주십시오. |
| 세션 만료 예고 | {남은 시간} 후 자동으로 로그아웃됩니다. 계속 이용하려면 연장해 주십시오. (팝업 S1) |
| 계정 전환 확인 | 저장하지 않은 내용이 있습니다. 저장한 뒤 계정을 전환하시겠습니까? |

## 5. 체크리스트
- [ ] 로그인 방식(기본·SNS·패스키)과 {변수} 값을 프로젝트에 맞게 정했는가
- [ ] 로그인 실패 문구가 계정 존재 여부를 드러내지 않는가
- [ ] CAPTCHA 노출·계정 잠금 횟수가 비밀번호 정책과 맞는가
- [ ] 로그인 필요 기능에서 로그인 후 원래 작업으로 돌아오고, 입력값이 유지되는가
- [ ] 로그인 상태 유지 기본값이 해제이고 공용 기기 안내가 있는가
- [ ] 2차 인증을 쓰면 인증번호 유효 시간·재발송 제한이 화면에 보이는가
- [ ] 세션 유지 시간을 정했고, 만료 전 경고(S1)와 만료 후 안내(S2)가 있는가
- [ ] 자동 완성 허용, 키보드만으로 로그인 가능, 초점 순서가 자연스러운가
