# 알림 정책

## 1. 목적
사용자가 꼭 필요한 정보를 놓치지 않으면서 과도한 알림에 방해받지 않도록 알림 유형, 노출 방식, 목록 관리, 수신 설정과 운영 기준을 일관되게 정의한 UX 정책 체계 (웹 데스크톱 기준)

## 2. 규칙

### 알림 유형 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 알림 분류 | 시스템(점검·공지), 업무(요청·승인·처리 상태), 보안(로그인·비밀번호 변경), 마케팅(선택 수신)으로 구분<br>유형마다 아이콘과 이름표를 일관되게 사용 | 공통 |
| 중요도 구분 | 긴급·일반·정보 3단계로 구분<br>긴급 알림은 사용자가 확인하기 전까지 유지 | 공통 |
| 필수 알림 | 보안, 약관·개인정보 변경 알림은 수신 거부 불가<br>필수 알림임을 화면에 명시 | 공통 |

### 채널·노출 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 인앱 알림 | 헤더 알림 아이콘에 읽지 않은 알림이 있으면 빨간 점 표시 (건수 숫자는 표시하지 않음)<br>빨간 점에는 스크린리더용 '새 알림 있음' 텍스트 제공<br>아이콘 클릭 시 알림 목록 패널 노출 | 사용자 · 관리자 |
| 토스트·배너 | 토스트는 단순 완료 안내에만 사용, {5초} 이상 노출<br>마우스를 올리거나 키보드 초점이 가면 사라지지 않고 멈춤<br>오류·긴급 알림은 토스트 대신 얼럿 또는 닫기 전까지 유지되는 배너 사용 | 공통 |
| 외부 채널 (이메일·브라우저 푸시) | 이메일은 필수·선택 알림 모두 지원<br>브라우저 푸시는 사용자 동의 후 제공 (추가 제안)<br>채널별 수신 여부는 설정에서 관리 | 사용자 |

### 목록·관리 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 알림 목록 | 최신순 정렬, 읽음·안 읽음을 색상 외 텍스트나 아이콘으로도 구분<br>유형별 필터는 검색·필터링 정책과 동일한 구조 사용 | 사용자 · 관리자 |
| 읽음 처리 | 알림 클릭 시 읽음 처리 후 관련 화면으로 이동<br>모두 읽음 처리와 개별 삭제 제공 | 사용자 · 관리자 |
| 보관 기간 | 읽은 알림은 n일 후 자동 삭제 (예: 90일)(선택)<br>보관 기간을 화면에 안내(선택) | 공통 |

### 설정/운영 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 수신 설정 | 내 정보에서 유형·채널별 켜기/끄기 제공 (광고성 정보는 문자·이메일·앱 푸시 채널별)<br>필수 알림은 비활성 상태와 사유를 함께 표시<br>광고성 정보 동의·철회 시 {14일} 이내 처리 결과 통지, {2년}마다 수신 동의 여부 확인 안내 (광고 없이 별도 발송) | 사용자 |
| 발송 제어 | 동일 이벤트 중복 발송 방지, 짧은 시간 내 다수 알림은 묶어서 표시<br>광고성 정보는 야간(21~08시) 발송 금지, 야간 수신은 별도 동의 시에만 | 관리자 |
| 접근성 | KWCAG 2.2 응답시간 조절 기준에 따라 자동으로 사라지는 알림은 시간 연장·일시정지 가능<br>스크린리더가 읽을 수 있는 알림 안내 제공 | 공통 |

## 3. 흐름 — 알림 발송·확인 플로우
(단계·화면·분기 이름 순서, 연결 관계는 피그마 흐름도 참고)
- 발생
- 발송
- 확인
- 이벤트 발생 (시스템·업무·보안·마케팅)
- 수신 설정 확인 (유형·채널별)
- 인앱 알림 등록 (중요도 표시)
- 외부 채널 발송 (이메일·브라우저 푸시)
- 발송 안 함 (필수 알림은 설정과 무관하게 발송)
- 헤더 알림 아이콘에 빨간 점 표시
- 알림 목록 확인 (유형별 필터)
- 읽음 처리 후 관련 화면 이동
- 분기: 수신 ON / 수신 OFF / 채널 수신 ON
