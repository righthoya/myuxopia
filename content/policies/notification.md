# 알림 정책

## 1. 목적
꼭 필요한 알림은 놓치지 않고, 불필요한 알림은 줄이도록 기준을 정합니다.

## 2. 규칙 표

|---|---|---|---|---|---|

| 알림 유형 | 중요도 구분 | 공통 | 긴급·일반·정보 3단계로 구분합니다. 긴급 알림은 사용자가 확인하기 전까지 유지합니다 | 필수 | — |

| 설정/운영 | 접근성 | 공통 | KWCAG 2.2 응답 시간 조절 기준에 따라 자동으로 사라지는 알림은 시간 연장·일시정지가 가능해야 합니다. 스크린리더가 읽을 수 있게 알림을 안내합니다 | 필수 | — |

## 3. 흐름 (알림 발송·확인)
![알림 발송·확인 흐름. 발생: 시스템·업무·보안·마케팅 이벤트가 발생합니다. 발송: 유형·채널별 수신 설정을 확인해 수신이 꺼져 있으면 보내지 않습니다(필수 알림은 설정과 관계없이 발송). 수신이 켜져 있으면 중요도를 표시해 인앱 알림으로 등록하고, 해당 채널 수신이 켜져 있으면 이메일·브라우저 푸시로도 보냅니다. 확인: 헤더 알림 아이콘에 읽지 않은 건수가 표시되고, 사용자는 알림 목록에서 유형별로 확인한 뒤 알림을 누르면 읽음 처리되고 관련 화면으로 이동합니다.](/flows/notification.svg)

## 4. 예시 문구 (합니다체)
| 상황 | 문구 |
|---|---|
| 알림 패널 제목 | 알림 ({읽지 않은 건수}) |
| 알림 없음 | 새 알림이 없습니다. |
| 모두 읽음 | 모두 읽음으로 표시 |
| 필수 알림 설정 사유 | 보안·약관 관련 알림은 서비스 이용에 꼭 필요해 끌 수 없습니다. |
| 브라우저 푸시 동의 | {알림 내용}을 브라우저 알림으로 받으시겠습니까? (팝업 N3) |
| 보관 기간 안내 | 읽은 알림은 {보관 기간} 후 자동으로 삭제됩니다. |
| 묶음 알림 | {알림 제목} 외 {개수}건 |
| 처리 상태 알림 | {요청명} 요청이 {처리 상태}되었습니다. |
| 점검 공지 배너 | {점검 일시}에 서비스 점검이 진행됩니다. (팝업 S7) |
| 수신 설정 변경 | 알림 설정이 저장되었습니다. |

## 5. 체크리스트
- 알림 유형(시스템·업무·보안·마케팅)과 중요도(긴급·일반·정보)를 정했습니까?
- 필수 알림이 무엇인지 정했고, 설정 화면에서 끌 수 없음과 사유가 보입니까?
- 헤더 아이콘에 읽지 않은 건수가 보이고, 많을 때 줄여 표시하는 기준이 있습니까?
- 오류·긴급 알림은 닫기 전까지 유지됩니까?
- 읽음·안 읽음이 색 외의 방법으로도 구분됩니까?
- 알림을 누르면 읽음 처리되고 관련 화면으로 갑니까?
- 중복 발송 방지, 묶음 표시, 마케팅 야간 발송 제한이 있습니까?
- 자동으로 사라지는 알림을 연장·일시정지할 수 있습니까?
