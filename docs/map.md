# [MAP] UX Guide 웹 기획 (구 UX/UI 표준정의서)
label: wayfinder:map · 상태: 차팅 완료 (2026-09-24)

## Destination
개발에 바로 들어갈 수 있는 **기획서 확정본**. 대상 사용자, 웹화면 역할, 원천 데이터 방식, IA, 화면 목록, 핵심 기능이 모두 결정된 상태.
(가정: 사용자가 도착점을 따로 고르지 않아 '개발 착수용 기획서'로 둠. 바꾸려면 이 줄만 수정)

## Notes
- **이름: 'UX Guide'** (2026-09-25 결정)
- **성격: UI 정책서가 아니라 UX 정책서** (2026-10-05). 파운데이션·컴포넌트는 다루지 않음
- **원본 우선순위: 피그마 = 기준, PPTX = 오래된 참고자료.** PPTX 중 낡은 부분은 Claude가 업데이트해도 됨 (사용자 승인)
- 원천 자료: ① PPTX 표준정의서(How) ② 피그마 'UX 표준 정책_v1.0'(정책 목적·방향 + 기능 정책: 검색·필터, 문의). 요약은 `standard-summary.md`
- 사용 스킬: PPTX 읽기 → pptx 스킬 (텍스트 추출 우선), 대화형 결정 → 짧은 Q&A, 화면 초안 → artifact-design
- **MVP 원칙 (2026-09-25): 최소 범위로 만들되 확장 가능한 구조** (토큰·문구 사전·유동 그리드)
- 프로젝트: claude.ai 'Myuxopia'(마이유토피아) — 바이브코딩으로 만드는 UX 표준 웹 (2026-09-25 이전)
- **작업 방식: 바이브코딩.** 내용·화면 수정은 모두 코드에서 Claude와 함께 → 데이터는 사람이 읽고 고치기 쉬운 파일 구조로
- 사용자 선호: 설명 최소화, 바로 실행, 목록 5개 이하
- **토큰 절약 규칙** (모든 세션 공통)
  1. 새 세션은 이 map만 읽기. 티켓 본문은 필요할 때만 `tickets.md`에서 해당 섹션만 확인
  2. 한 세션에 티켓 1개만 처리 (리서치 티켓은 예외). 끝나면 새 채팅으로 시작
  3. PPTX는 한 번만 읽기: 텍스트 추출(markitdown) → `standard-summary.md`에 저장하고 이후엔 그 요약만 사용
  4. 슬라이드 이미지 렌더링은 텍스트로 부족한 장만 (이미지는 토큰 비쌈)
  5. 리서치는 가벼운 모델(sonnet/haiku) 서브에이전트 1개로, 결과는 요약 10줄 이내

- [T2. 대상 사용자](tickets.md#t2): 1순위 프로덕트 디자이너. 장면 4개(설계 규칙 확인·정책 재사용·문구·핸드오프), 가져가는 것 4개(텍스트·토큰 복사, 예시 UI, 체크리스트) 모두 → 항목별 복사 버튼·고정 URL
- [T4. 웹 역할](tickets.md#t4): MVP 열람 전용 뷰어(보기·검색·복사·고정 링크), 내용 수정은 바이브코딩으로 코드 속 데이터 파일 직접 수정(웹 편집 없음). 확장 = 항목별 의견·피드백
- [T5. 원천 데이터](tickets.md#t5): 최종 원본 = 피그마, 코드는 사본(피그마→Claude가 코드 갱신). 가이드 본문·문구 가이드 = MD, 토큰·웹 UI 라벨 = JSON
- [T6. 메뉴 구조](tickets.md#t6): 1depth 5개(UX 정책·기능 정책·화면 패턴·팝업·문구·접근성), 기능 정책에 로그인·알림 추가. 공통 요소 4개(복사·변수 강조·등급 배지·피그마 연결) → [IA](ia.md)
- 메뉴 개정 (2026-10-05): **UX 정책서로 한정 → 파운데이션·컴포넌트 제외.** 대신 '팝업·문구' 메뉴 신설, 기본 팝업 32종(시스템 8·계정 8·데이터 9·개인정보 4·문의/알림 3) → 1차 MVP 13종 / 2차 19종으로 구분, 버튼 순서 왼쪽 취소·오른쪽 실행 확정 → [팝업 목록](policies/popups.md)

- 정책 카테고리 (2026-10-01): 유형 태그(공통·B2B·플랫폼·B2C·공공) 방식, MVP 9개 = 회원가입·로그인·인증·비밀번호·권한·역할·검색·필터링·알림·문의·개인정보 처리·오류·장애 처리. 2단계 후보 16개 → [카탈로그](policy-categories.md)
