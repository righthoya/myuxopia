# 권한·역할 정책

## 1. 목적
사용자의 역할에 따라 접근 가능한 메뉴와 기능을 명확히 구분하고, 권한이 없을 때도 사용자가 다음 행동을 알 수 있도록 권한 체계, 안내, 부여·변경, 보안 기준을 일관되게 정의한 UX 정책 체계 (웹 데스크톱 기준)

## 2. 규칙

### 권한 체계 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 역할 구분 | 기본 역할 4단계: 비회원 · 사용자 · 관리자 · 최고 관리자<br>모든 정책에서 이 이름만 사용 (슈퍼관리자·운영자 등 다른 이름 금지)<br>서비스별 추가 역할은 {추가 역할: 예) 준사용자}로 정의 | 공통 |
| 권한 단위 | 메뉴 접근, 기능(조회·등록·수정·삭제), 데이터 범위 단위로 부여<br>역할별 권한은 권한 표로 관리 | 관리자 |
| 최소 권한 원칙 | 업무에 필요한 권한만 부여<br>신규 계정의 기본값은 최소 권한 | 관리자 |

### 권한 없음 안내 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 메뉴 노출 | 접근 권한이 없는 메뉴는 숨김이 기본<br>노출이 필요한 경우 비활성 처리하고 사유 안내 | 사용자 · 관리자 |
| 직접 접근 차단 | 권한이 없는 메뉴·버튼·링크는 노출하지 않는 것이 기본<br>URL 직접 입력 등으로 들어온 경우의 403 화면·문구는 오류·장애 처리 정책 참고 | 공통 |
| 기능 버튼 제어 | 권한 없는 기능 버튼은 비활성 처리<br>마우스오버·키보드 초점 시 사유 툴팁 노출 | 사용자 · 관리자 |

### 권한 부여·변경 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 권한 부여 | 관리자 화면에서 사용자 검색 후 역할 지정<br>변경 전 확인 안내로 실수 방지 | 관리자 |
| 권한 요청 (추가 제안) | 사용자가 관리자에게 권한 신청하는 정책<br>관리자가 승인·반려하고 결과를 알림으로 안내<br>무작위 권한 신청 제한(1시간 기준) | 사용자 · 관리자 |
| 변경 반영·알림 | 변경 반영 시점을 화면에 명시<br>변경 시 대상 사용자에게 알림 발송 | 공통 |

### 보안/운영 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 관리자 권한 보호 | 관리자 계정의 추가 인증은 로그인 정책의 '2단계 인증' 참고<br>마지막 관리자 권한은 해제 불가 | 관리자 |
| 이력 관리 | 권한 부여·변경·회수 이력은 일시와 처리자 기록<br>관리자 화면에서 조회 가능 | 관리자 |
| 접근성 | 비활성 상태와 사유는 색상 외 텍스트로도 제공<br>스크린리더가 읽을 수 있는 권한 안내 제공 | 공통 |

## 3. 흐름 — 권한 등록 플로우
(단계·화면·분기 이름 순서, 연결 관계는 피그마 흐름도 참고)
- 진입
- 권한 확인
- 결과
- 메뉴·기능 접근 시도
- 로그인 여부 확인
- 권한 확인 (역할·기능·데이터 범위)
- 로그인 필요 안내 (로그인 후 원래 화면 복귀)
- 화면·기능 정상 이용
- 권한 없음 안내 (사유, 권한 요청 방법, 이전 화면 이동)
- 권한 요청 (추가 제안) (사유 입력 → 관리자 승인·반려)
- 분기: 로그인 상태 / 비로그인
- 분기: 권한 없음 / 권한 있음
