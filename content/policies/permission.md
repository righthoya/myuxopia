# 권한 정책

## 1. 목적
역할에 따라 쓸 수 있는 메뉴·기능을 나누고, 권한이 없을 때 다음 행동을 안내합니다.

## 2. 규칙 표
| 유형 | 항목 | 대상 | 내용 | 등급 | {변수} |
|---|---|---|---|---|---|
| 권한 체계 | 역할 구분 | 공통 | {역할: 비회원 · 사용자 · 관리자} 3단계를 기본으로 구분합니다. 서비스 특성에 따라 준사용자, 운영자, 최고(슈퍼) 관리자 등으로 세분화할 수 있습니다 | 필수 | 역할 |
| 권한 체계 | 권한 단위 | 관리자 | 메뉴 접근, 기능(조회·등록·수정·삭제), 데이터 범위 단위로 권한을 부여합니다. 역할별 권한은 권한 표로 관리합니다 | 필수 | — |
| 권한 체계 | 최소 권한 원칙 | 관리자 | 업무에 필요한 권한만 부여합니다. 신규 계정의 기본값은 최소 권한입니다 | 필수 | — |
| 권한 없음 안내 | 메뉴 노출 | 사용자 · 관리자 | 접근 권한이 없는 메뉴는 숨기는 것이 기본입니다. 보여야 하는 경우 비활성으로 처리하고 사유를 안내합니다 | 권장 | — |
| 권한 없음 안내 | 직접 접근 차단 | 공통 | 주소 직접 입력 등 권한 없는 접근은 권한 없음 화면을 보여 줍니다. 사유, 권한 요청 방법, 이전 화면·메인 이동 버튼을 제공합니다 (팝업 S4) | 필수 | — |
| 권한 없음 안내 | 기능 버튼 제어 | 사용자 · 관리자 | 권한 없는 기능 버튼은 비활성으로 처리하고, 마우스오버·키보드 초점 시 사유를 툴팁으로 보여 줍니다 | 권장 | — |
| 권한 부여·변경 | 권한 부여 | 관리자 | 관리자 화면에서 사용자를 검색해 역할을 지정합니다. 변경 전 확인 안내로 실수를 막습니다 | 필수 | — |
| 권한 부여·변경 | 권한 요청 | 사용자 · 관리자 | 사용자가 사유를 입력해 관리자에게 권한을 신청하고, 관리자가 승인·반려하면 결과를 알림으로 안내합니다. 같은 신청은 {재신청 제한: 1시간에 1회}로 제한합니다 | 선택 | 재신청 제한 |
| 권한 부여·변경 | 변경 반영·알림 | 공통 | 변경이 반영되는 시점을 화면에 명시하고, 변경되면 대상 사용자에게 알림을 보냅니다 | 권장 | — |
| 보안/운영 | 관리자 권한 보호 | 관리자 | 관리자 로그인 시 추가 인증(2차 인증)을 권장합니다. 마지막 남은 관리자의 권한은 해제할 수 없습니다 | 필수 | — |
| 보안/운영 | 이력 관리 | 관리자 | 권한 부여·변경·회수 이력을 일시와 처리자와 함께 기록하고, 관리자 화면에서 조회할 수 있게 합니다 | 필수 | — |
| 보안/운영 | 접근성 | 공통 | KWCAG 2.2 접근 가능한 인증 기준을 지킵니다. 비활성 상태와 사유는 색 외에 텍스트로도 제공하고, 스크린리더가 읽을 수 있게 안내합니다 | 필수 | — |

## 3. 흐름 (권한 확인)
![권한 확인 흐름. 진입: 사용자가 메뉴나 기능에 접근합니다. 권한 확인: 먼저 로그인 여부를 확인해 비로그인이면 로그인 필요 안내를 보여 주고, 로그인 후 원래 화면으로 돌아옵니다. 로그인 상태면 역할·기능·데이터 범위 권한을 확인합니다. 결과: 권한이 있으면 화면과 기능을 정상 이용합니다. 권한이 없으면 사유, 권한 요청 방법, 이전 화면 이동을 안내하고, 사용자는 사유를 입력해 권한을 요청할 수 있습니다(관리자 승인·반려).](/flows/permission.svg)

## 4. 예시 문구 (합니다체)
| 상황 | 문구 |
|---|---|
| 권한 없음 화면 | 이 메뉴를 이용할 권한이 없습니다. 필요하면 관리자에게 권한을 요청해 주십시오. (팝업 S4) |
| 비활성 버튼 툴팁 | {기능}할 권한이 없습니다. |
| 비활성 메뉴 사유 | {역할}만 이용할 수 있는 메뉴입니다. |
| 권한 변경 확인 | {사용자명}의 역할을 {변경 전 역할}에서 {변경 후 역할}로 변경하시겠습니까? |
| 권한 변경 반영 | 변경한 권한은 다음 로그인부터 적용됩니다. |
| 권한 변경 알림 | 회원님의 역할이 {변경 후 역할}로 변경되었습니다. |
| 권한 요청 완료 | 권한 요청이 접수되었습니다. 처리 결과는 알림으로 알려 드립니다. |
| 권한 요청 반려 | 권한 요청이 반려되었습니다. 사유: {반려 사유} |
| 재신청 제한 | 같은 권한은 {재신청 제한}만 요청할 수 있습니다. 잠시 후 다시 요청해 주십시오. |
| 마지막 관리자 해제 | 마지막 관리자의 권한은 해제할 수 없습니다. 다른 관리자를 먼저 지정해 주십시오. |

## 5. 체크리스트
- 역할 구분과 역할별 권한 표(메뉴·기능·데이터 범위)를 정했습니까?
- 신규 계정 기본값이 최소 권한입니까?
- 권한 없는 메뉴는 숨기거나, 보이면 비활성과 사유를 함께 보여 줍니까?
- 주소 직접 입력 시 권한 없음 화면에 사유·요청 방법·이동 버튼이 있습니까?
- 비활성 버튼의 사유가 마우스와 키보드 초점 모두에서 보입니까?
- 권한 변경 전 확인, 반영 시점 안내, 대상자 알림이 있습니까?
- 마지막 관리자 권한 해제가 막혀 있습니까?
- 권한 부여·변경·회수 이력이 일시·처리자와 함께 남습니까?
