# 비밀번호 정책

## 1. 목적
사용자가 비밀번호를 안전하게 설정하고 잊었을 때도 쉽게 복구할 수 있도록 입력 규칙, 찾기·재설정, 변경, 보안 기준을 일관되게 정의한 UX 정책 체계 (웹 데스크톱 기준)

## 2. 규칙

### 비밀번호 설정 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 비밀번호 입력 규칙 | 영문·숫자·특수문자 조합 8자 이상 (서비스 기준에 따라 조정)<br>규칙은 입력 전 helper text로 상시 노출<br>아이디, 연속·반복 문자열 사용 불가 | 공통 |
| 입력 중 실시간 안내 | 충족한 규칙은 체크 아이콘과 텍스트로 표시<br>색상만으로 상태를 구분하지 않음<br>비밀번호 강도 표시 (추가 제안) | 공통 |
| 비밀번호 확인 입력 | 일치 여부 실시간 안내<br>불일치 시 helper text로 오류 안내<br>표시/숨김 토글 제공, 기본값은 숨김 | 공통 |

### 찾기·재설정 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 본인 확인 | 이메일 또는 휴대폰 인증 중 선택<br>인증번호 유효시간 {5분}, 남은 시간 표시<br>재발송 {1분에 1회 · 하루 5회} 제한<br>가입 여부와 무관한 동일 안내는 로그인 정책의 통일 문구 원칙 적용 | 비회원 · 사용자 |
| 새 비밀번호 설정 | 인증 완료 후에만 재설정 화면 노출<br>재설정 링크는 유효시간 내 1회만 사용, 이전 비밀번호와 동일하게 설정 불가<br>B2B: 본인 재설정 대신 관리자가 초기화(임시 비밀번호 발급), 첫 로그인 시 변경 | 비회원 · 사용자 |
| 재설정 완료 | 완료 안내와 함께 로그인 화면으로 이동<br>자동 로그인은 하지 않음 | 비회원 · 사용자 |

### 비밀번호 변경 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 자발적 변경 | 내 정보에서 현재 비밀번호 확인 후 변경<br>새 비밀번호는 설정 규칙과 동일하게 적용<br>B2B: 분실 시 관리자에게 초기화 요청 (관리자가 본인 확인) | 사용자 · 관리자 |
| 주기적 변경 안내 (추가 제안) | 일정 기간(예: 90일) 경과 시 변경 권유<br>‘다음에 변경하기’ 선택 가능 | 사용자 · 관리자 |
| 변경 완료 후 처리 | 다른 기기의 로그인 세션 종료 안내<br>변경 완료 알림 메일 발송 | 사용자 · 관리자 |

### 보안/운영 정책

| 항목 | 내용 | 대상 |
|---|---|---|
| 오류 문구 | 규칙 위반 항목을 구체적으로 안내<br>계정 존재 여부 비노출 원칙은 로그인 정책 참고 | 공통 |
| 시도 제한 | 로그인 정책의 실패 기준과 같음<br>B2B: 연속 실패 시 관리자 초기화로 처리<br>제한 시간과 남은 시간 안내 | 공통 |
| 접근성 | KWCAG 2.2 접근 가능한 인증 기준 준수<br>오류 발생 시 해당 입력창으로 초점 이동<br>인증 시간 연장 가능, 비밀번호 관리자 자동 완성 허용 | 공통 |

## 3. 흐름 — 비밀번호 찾기·재설정 플로우
(단계·화면·분기 이름 순서, 연결 관계는 피그마 흐름도 참고)
- 진입
- 본인 확인
- 재설정
- 완료
- 로그인 화면 (‘비밀번호 찾기’ 선택)
- 비밀번호 찾기 진입
- 계정 정보 입력 (가입 여부와 무관하게 동일 안내)
- 인증 수단 선택 (이메일 / 휴대폰)
- 인증번호 입력 (유효시간 안내, 재발송 제한)
- 일정 시간 인증 제한 (연속 실패 n회)
- 새 비밀번호 입력 (규칙 실시간 안내)
- 새 비밀번호 확인 (일치 여부 실시간 안내)
- 변경 완료 안내 (로그인 화면 이동)
- 로그인 화면
- 분기: n회 실패 / 인증 성공
