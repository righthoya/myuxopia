# 오류·장애 처리 정책

## 1. 목적
오류나 장애가 생겨도 사용자가 상황을 이해하고 다음 행동을 할 수 있도록 입력 오류, 시스템 오류, 에러 페이지(403·404·500), 점검·장애 안내 기준을 정의합니다.

## 2. 규칙

### 입력 오류 정책
- **인라인 오류**: 입력 필드 바로 아래 문장으로 안내 / 아이콘과 텍스트를 함께 써서 색상만으로 구분하지 않음
- **오류 문구**: 무엇이 잘못됐는지와 고치는 방법을 함께 안내 / 사용자를 탓하는 표현, 개발 용어 사용 금지
- **제출 시 처리**: 첫 오류 필드로 초점 이동 / 오류 후에도 입력값 유지 (비밀번호 제외)

### 시스템 오류 정책
- **일시적 오류**: 오류 팝업으로 안내하고 다시 시도 버튼 제공 / {오류 코드}를 함께 표시해 문의 시 활용
- **네트워크 오류**: 인터넷 연결 확인 안내 / 연결이 복구되면 자동 재시도 (추가 제안)
- **중요 작업 오류**: 저장·결제 등 중요한 작업은 처리 결과를 확인할 수 있게 안내 / 처리 중 버튼 비활성으로 중복 실행 방지

### 에러 페이지 정책
- **403 권한 없음**: 접근 권한이 없다는 사실과 이유 안내 / 이전 페이지·홈 이동, 권한 요청 경로 제공
- **404 페이지 없음**: 주소가 바뀌었거나 삭제된 페이지임을 안내 / 홈 이동과 주요 메뉴 링크 제공
- **500 서버 오류**: 잠시 후 다시 시도하도록 안내 / 새로고침·홈 이동, {문의 채널}과 {오류 코드} 제공

### 점검·장애 운영 정책
- **점검 사전 안내**: 점검 일시와 영향 범위를 {사전 공지: 3일 전}에 미리 공지 / 로그인 후 팝업·배너로 한 번 더 안내
- **점검 중 화면**: 점검 시간과 종료 예정 시각 안내 / {문의 채널} 제공
- **장애 공지·기록**: 장애 발생 시 공지와 복구 예정 시간 안내 / 오류 로그 기록, 로그와 화면에 개인정보 미포함

## 3. 요약 표
| 유형 | 세부 유형 | 대상 | 내용 요약 |
|---|---|---|---|
| 입력 오류 | 인라인 오류 | 공통 | 필드 아래 문장 안내, 아이콘·텍스트 병행 |
| 입력 오류 | 오류 문구 | 공통 | 원인과 해결 방법 함께 안내, 비난·개발 용어 금지 |
| 입력 오류 | 제출 시 처리 | 공통 | 첫 오류 필드로 초점 이동, 입력값 유지 |
| 시스템 오류 | 일시적 오류 | 공통 | 오류 팝업 + 다시 시도, {오류 코드} 표시 |
| 시스템 오류 | 네트워크 오류 | 공통 | 연결 확인 안내, 복구 시 자동 재시도 |
| 시스템 오류 | 중요 작업 오류 | 사용자 | 처리 결과 확인 안내, 중복 실행 방지 |
| 에러 페이지 | 403 권한 없음 | 사용자 | 권한 없음 안내, 이전·홈 이동, 권한 요청 경로 |
| 에러 페이지 | 404 페이지 없음 | 공통 | 없는 페이지 안내, 홈·주요 메뉴 링크 |
| 에러 페이지 | 500 서버 오류 | 공통 | 재시도 안내, 새로고침·홈 이동, {문의 채널}·{오류 코드} |
| 점검·장애 운영 | 점검 사전 안내 | 공통 | 점검 일시·범위 {사전 공지: 3일 전} 공지, 팝업·배너 안내 |
| 점검·장애 운영 | 점검 중 화면 | 공통 | 점검 시간·종료 예정 시각, {문의 채널} |
| 점검·장애 운영 | 장애 공지·기록 | 관리자 | 장애 공지·복구 예정 안내, 로그 기록(개인정보 제외) |

## 4. 흐름 (오류 발생 시 처리 플로우)
- 단계: 발생 → 판단 → 안내 → 복구
- 사용자 요청 (화면 이동·저장·조회)
- 오류 발생
- 오류 유형 판단 (입력 / 권한 / 페이지 / 서버)
- 서버·네트워크 오류 팝업 (오류 코드 표시)
- 다시 시도 (입력값 유지)
- 500 에러 페이지·장애 공지 ({문의 채널} 안내)
- 요청 정상 처리
- 결과 안내 (토스트·완료 화면)
- 작업 이어서 진행
- 원래 화면
- 분기: {재시도 실패: n회} / 재시도 성공
